# EffectScript Plan 13: The Effect docs in EffectScript

> **For agentic workers:** execute task by task with TDD. Decisions are recorded in `docs/adr/`.
> Gate every commit: `pnpm check && pnpm lint && git commit …`.

**Goal:** every Effect doc and code sample in this repository has an EffectScript edition,
generated by the reverse compiler and kept in step with upstream:

- the `ai-docs` examples;
- `LLMS.md`;
- the guides: package READMEs, `SCHEMA.md` and friends, and the migration guides;
- every JSDoc example in every package.

People read it, the site renders it (phase 10), and AI tooling trains on it, including a parallel
TypeScript ↔ EffectScript corpus.

**Architecture:** a private package `packages/effectscript/effect-docs` (`@effectscript/effect-docs`).

- **`src/translate.ts` (pure):**
  - `convertBlock(code)`: `toEffectScript`, with `changed`/`notes`;
  - `convertMarkdown(md)`: rewrites `ts`/`typescript`/`tsx` fences;
  - `jsdocExamples(source)`: the code fences in each JSDoc block, with the documented symbol and
    the example's title;
  - `tokens(code)`: a TypeScript-scanner token count.
- **`scripts/generate.ts`:** walks the repository's sources, writes `content/`, and has a
  `--check` mode.
- **Output (`content/`, committed, generated):**
  - `ai-docs/**`: `.efx` for each example, and `index.md` with converted fences;
  - `LLMS.efx.md`: the `ai-docgen` layout (same ordering, titles and inline examples) with
    `efx` code and links;
  - `guides/<repo path>.md`: package READMEs, `packages/effect/*.md` (not the CHANGELOG), and
    `migration/*.md`;
  - `api/<package>/<module>.md`: per module, each documented symbol with its examples in
    EffectScript;
  - `corpus.jsonl`: one line per example, `{ source, symbol?, title?, ts, efx, changed }`;
  - `REPORT.md`: per area, the counts (blocks, re-sugared, unchanged, left as TS) and the token
    totals.

**Spec:** §0 (evidence for the pitch), §6 (reverse compiler), §8 (skill references), §9 (site
content).

**Decisions:** ADR-0050 (new) for the corpus, its layout and freshness. Builds on ADR-0030
(conversion safety), ADR-0031 and ADR-0015 (release automation regenerates).

## Global Constraints

- Upstream files (`ai-docs/`, `packages/*/src`, `migration/`) are read, never written.
- **The conversion contract:** every `efx` block compiles back to its original TypeScript (ADR-0030;
  `toEffectScript` verifies). A block that doesn't parse stays a `ts` fence.
- **Fences:** a block TypeScript can parse is valid EffectScript (the superset), so it becomes an
  `efx` fence whether or not it changed. The corpus records `changed`.
- **Deterministic output:** sorted walks and stable formatting. `generate --check` fails on a
  stale `content/`.
- **Generator speed:** under 30 s for the whole repository.

## Review Focus

1. Fences inside JSDoc (` * ` prefixes, indentation in namespaces, doctest markers such as
   `ts import.meta.vitest`) are extracted exactly and lose no lines. *(Task 1)*
2. Markdown that isn't code (inline backticks, `~~~` fences, fences in lists, a `ts` fence that
   doesn't parse) is untouched, apart from the fences that are converted. *(Task 1)*
3. Symbols are attributed correctly for namespace members, overloads, and examples on the
   module's own top comment. *(Task 1)*
4. `--check` detects any drift, including a deleted upstream file. *(Task 2)*
5. The report's numbers match the content (no double counting between areas). *(Task 3)*

### Task 1: The translation library

- `src/translate.ts` with:
  - `convertBlock`;
  - `convertMarkdown`, which handles fence info strings and indented fences;
  - `jsdocExamples`, which strips the ` * ` margin, keeps the symbol (namespace-qualified, like
    `Option.Option.Value`) and the `**Example** (Title)` line;
  - `tokens`.
- **Tests:** each Review Focus 1–3 case, and a round trip on every changed block of a fixture
  (`toTypeScript(efx)` is token-equal to the original).

### Task 2: The generator and `content/` (ADR-0050)

- `scripts/generate.ts [--check]`, which writes:
  - `ai-docs/**`;
  - `LLMS.efx.md`, a port of `packages/tools/ai-docgen`'s ordering rules;
  - `guides/**`;
  - `api/**`;
  - `corpus.jsonl`.

  The package has a `codegen` script, so `pnpm codegen` covers it.
- **Tests:**
  - `--check` passes on the committed output;
  - drift fails, including a deleted source;
  - `LLMS.efx.md` has the same section titles, in the same order, as `LLMS.md`.

### Task 3: Report, docs

- `REPORT.md` and its numbers, with a test that they add up against `corpus.jsonl`.
- The README of the docs package, and spec links: §8 (the skill references use it) and §9 (the
  site renders it).
- COMPATIBILITY row.
- This plan's execution record.

**Deferred minors:**

- **Markdown edge cases:**
  - a `ts` fence nested in another fence is converted;
  - code blocks indented 4+ spaces are treated as fences;
  - an info string like `ts-node` becomes `efx-node`;
  - code that doesn't parse gets re-indented.
- **`drift`** counts dotfiles (`.DS_Store`), and the generator reads untracked working-tree files.
- **Converted fences** start with a blank line where an import was removed.
- **`.tsx`:** sources and fences aren't handled on API pages.
- **API pages:** duplicate headings when an interface and a constant share a name.
- **Scope:** guides include tools' READMEs, and `test/` and `fixtures/` folders aren't skipped.
- **`ai-docs` fixtures** that examples import aren't copied.
- **Text encoding:** CRLF and BOM inputs give mixed line endings.
- **Diffs:** `.gitattributes` doesn't mark `content/` as `linguist-generated`.
- **Codegen race:** running codegen in parallel could read a barrel file while it is being
  rewritten.
