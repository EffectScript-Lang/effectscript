# EffectScript Plan 16: The site (phase 10), built locally

> **For agentic workers:** execute task by task with TDD. Decisions are recorded in `docs/adr/`.
> Gate with `pnpm check && pnpm lint` on your paths and commit with explicit paths (another
> session shares the branch).

**Goal:** `packages/effectscript/site`, the effectscript.dev site, builds and runs locally
(`pnpm --filter @effectscript/site dev|build|preview`). It has:

- **The landing page** (spec §9.2): problem → solution, a VS Code-style before/after gallery of
  ten scenarios with real token counts, the strictness and agents section, the library
  constructs, zero risk, the roadmap, and install.
- **A two-way playground:** Monaco with our grammar, the compiler in a Web Worker, diagnostics,
  notes, presets, and a share hash.
- **Docs (Starlight at `/docs`):**
  - the language reference, generated from the fixtures;
  - guides;
  - the Effect docs in EffectScript (ADR-0050);
  - `llms.txt`.

Deployment (Alchemy to Cloudflare) is the user's publish step and isn't run.

**Architecture:**

- **Framework:** Astro 7, static output, with Starlight (docs), Tailwind 4, React 19 islands
  (gallery, token toggle, playground) and `astro-expressive-code` plus Shiki 4 with
  `source.efx` (the VS Code extension's grammar).
- **Build-time data** (`src/data/*.ts`, plain functions):
  - **Gallery:** the ten samples (`src/samples/<scenario>/{plain.ts,app.efx}`). The Effect TS pane
    comes from `toTypeScript(app.efx)`, so it can't drift. Token counts come from `gpt-tokenizer`
    (`o200k_base`).
  - **Reference:** pages from `core/test/fixtures` (as in the skill's `syntax.md`).
  - **Guides:** from the skill's `references/patterns.md` and `pitfalls.md`, one source of truth.
  - **The Effect docs:** from `effect-docs/content` (`LLMS.efx.md`, guides, the API index).
- **Playground** (`src/playground/`):
  - `worker.ts` runs `toTypeScript`/`toEffectScript` and posts code, diagnostics and notes;
  - `Playground.tsx`: two Monaco editors following the focused pane, a Problems list, presets,
    and `#code=` hash sharing (base64url, UTF-8).
- **Brand** (from `brand/`): zinc on ink, Inter Display and JetBrains Mono (local fonts), and the
  ƒx mark and favicons copied at build time. The "Follow @gunta85" call to action sits in the
  hero, the footer and after the playground.

**Spec:** §9 (all), §7.4 (grammar), §0 (narrative).

**Decisions:** ADR-0054 (new), the site's stack deviations and data sources: official
`monaco-editor` instead of the 0.0.x `@effect/monaco-editor` fork, build-time token counts, and
reusing the skill and corpus as content. Builds on ADR-0050, ADR-0051, ADR-0041 (grammar) and
ADR-0036.

## Global Constraints

- **Brand:** Effect-family monochrome, never the Effect logo, and no wording implying Effectful
  endorsement ("built on Effect"). Assets come from `brand/`, which is never edited.
- **Numbers on the page are computed** at build time from real code. The tokenizer is named
  honestly ("GPT-4o tokenizer, o200k_base").
- **Static output:** no server code, and the playground works offline from the built files.
- **Every gallery and playground sample compiles, and the gallery's EffectScript type-checks**
  against the workspace `effect` (a test).
- **Accessibility:** good contrast on zinc, keyboard access to the toggles, and readable at 375 px.
- Nothing is deployed.

## Review Focus

1. **The playground on bad input:** incomplete code, a huge paste, or a malicious share hash
   never freezes the page. The compiler runs in a worker, and a stale result never overwrites a
   newer one. *(Task 4)*
2. **Gallery counts:** the token counts and percentages on the page match `gpt-tokenizer` on the
   shown code (a test). *(Task 3)*
3. **Docs links:** "Open in playground" links and generated reference links resolve, and a build
   has no broken internal links. *(Tasks 2, 4)*
4. **Small screens:** at 375 px, the windows and the playground stack without horizontal page
   scroll. *(Tasks 3, 4, checked in the browser)*
5. **Freshness:** the reference and corpus sections are regenerated by the build, never
   hand-copied. *(Task 2)*

### Task 1: Scaffold and brand

- Create `packages/effectscript/site`: `package.json` (private, `@effectscript/site`), Astro
  config, Starlight at `/docs`, Tailwind 4, React, and `astro-expressive-code` with the `.efx`
  grammar.
- Copy the brand fonts, mark and favicons at build time (an integration hook, into `public/`,
  gitignored).
- Register the package in `tsconfig.packages.json` (if type-checked) and in vitest.
- **Test:** `astro build` succeeds and writes `index.html` and `docs/index.html`; the built CSS
  holds the brand tokens.

### Task 2: Docs content (generated)

- **Reference:** `src/content/docs/reference/*.md`, generated by `scripts/content.ts` from the
  fixtures (each construct with its EffectScript and TypeScript, plus an "Open in playground"
  link).
- **Guides:**
  - getting started (install, `efx init`, `efx setup`);
  - migrating with `efx convert`;
  - the skill's patterns and pitfalls;
  - editor setup;
  - strict rules (from the compiler's diagnostic table).
- **Effect in EffectScript:** `LLMS.efx.md` and the guides from `effect-docs/content`, with an
  API index.
- `public/llms.txt` and `llms-full.txt`.
- `content --check`, plus a test.
- **Tests:** generated pages exist for every fixture directory; internal links resolve in the
  built site; drift fails.

### Task 3: Landing page and gallery

- `src/samples/` holds the ten scenarios as `plain.ts` and `app.efx`, each with a short title.
- `src/data/gallery.ts` compiles them and counts tokens.
- `Window.astro` is the VS Code-style editor window: title bar, tabs, activity bar, gutter,
  minimap strip and status bar.
- `TokenToggle.tsx` colours token boundaries in the browser.
- Sections 1–9 of spec §9.2. The Follow call to action appears in the hero, the footer and after
  the playground.
- **Tests:**
  - every sample compiles and its EffectScript type-checks;
  - the page's numbers equal `gpt-tokenizer` on the shown code;
  - the build contains all ten scenarios.

### Task 4: Playground

- `/playground`: the worker, two Monaco editors (EffectScript ↔ TypeScript, following focus),
  the Problems list, notes, presets (the gallery samples), the share hash, and the Follow call to
  action.
- Debounced compiles, with a sequence number so stale results are dropped.
- **Tests:** `worker` unit tests (compile both ways, diagnostics, a stale sequence is ignored, a
  bad hash is rejected); a build includes the playground's assets. Then a real browser check
  (Browser pane): typing in the playground updates the other pane.

### Task 5: Docs

- Spec §9 status, COMPATIBILITY row, a site README (run, build, how content is generated), and
  this plan's execution record.

## Execution record

**Rulings:**

- **Monaco:** the official `monaco-editor` instead of the undocumented 0.0.x fork. Monaco
  highlights through Shiki (`@shikijs/monaco`), with the same grammar as the docs.
- **Generated docs inputs are gitignored,** and built by `scripts/content.ts` before `dev` and
  `build`, so they are fresh by construction rather than drift-checked.
- **`astro build --force`:** Astro's content cache kept a failed render (an empty page).
- **Token counts are computed at build time** (`o200k_base`). The "show tokens" toggle switches to
  pre-split token spans, so no tokenizer ships to the browser.
- **The `src/samples/*/plain.ts` files are display code:** they are excluded from the strict
  type check and lint. The EffectScript samples are type-checked by a test.
- **Type-checking found a mistake in the `errors` sample:** `timeout` fails with Effect's
  `TimeoutError`, not a user error.
- **The numbers:** 42% fewer tokens than Effect TypeScript and 40% fewer than plain TypeScript
  across the ten scenarios. The corpus: 4,019 examples, with 20.3% fewer tokens in the 1,714 that
  changed.
