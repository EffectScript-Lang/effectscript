# EffectScript Plan 25: The Bend model and `efx verify` (phase 19)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans. Steps use `- [ ]`. Execute task by task with TDD. Decisions are
> recorded in `docs/adr/`. Commit with explicit, gated paths (another session shares the branch):
> `pnpm check && pnpm lint && git commit <paths>`. Plan 24 must be done first.
>
> **Toolchain for this plan:** Bend at the pinned version (Task 1), on `PATH` or in `$BEND`. Tests
> that run Bend use `it.skipIf(bend === undefined)`, so a machine without it still passes. The
> proofs CI job (Task 13) installs it. Tasks 2 and 13 need it, because proofs are checked by Bend:
> the executing agent writes the proofs and `bend` is the test.

**Goal:** `efx verify` turns the provable subset of a `.efx` project into a Bend2 model under
`proofs/`. It runs every law as a property test and checks every proof file with Bend. It prints a
verdict per law. The examples' `bank` and `order` laws are proven in CI.

**Architecture:**

- **`src/compiler/bend/`** is a second emitter beside the TypeScript one. It is pure, with no
  `node:*` and no `typescript` imports (ADR-0004, ADR-0017). It reads the parsed project and has
  three parts:
  - **lowering** turns declarations into a small **model IR** (`ir.ts`), with:
    - ifs lifted into `.if<n>` helpers;
    - `await` split into `.k<n>` continuations;
    - lambdas converted to `.lam<n>`;
    - loops turned into `.for<n>`;
  - **`copies.ts`** decides `+`;
  - **`print.ts`** writes Bend text deterministically.
- **`opaque.ts`** spreads opacity to callers.
- **`laws.ts`** turns laws into claims and per-law files.
- **The CLI side** (`src/cli/bend.ts`, `src/cli/proofs.ts`, `src/cli/verify.ts`):
  - finds and runs the pinned Bend;
  - writes `proofs/` and checks it is fresh;
  - runs the steps of spec §6.1 (differential testing, kernel and lock come in Plan 26).

Everything the spike validated is kept exactly (spec §4.7): `Exit`, the `.if`, `.k`/`.go`,
`.lam`/`map_with` and `.for` shapes.

**Tech stack:** the existing parser and scope analysis, Bend 2.0.x (pinned), `effect/Arbitrary`
through `effectscript/laws` (Plan 24), Node `child_process` in the CLI only.

**Spec:** `docs/superpowers/specs/2026-10-04-effectscript-proofs-design.md` §3–§6, §8–§10;
ADR-0074, ADR-0076. Read the spec's §4 tables before Task 5.

## Global Constraints

- **The pin.** Bend's version is one constant, `bendVersion` in `src/compiler/bend/version.ts`
  (2.0.35 when this plan was written; use the newest release at Task 1 and record it). The
  sha256 values of its release archives sit next to it, copied from that release's `install.sh`.
  `efx` runs Bend with `BEND_NO_TELEMETRY=1`.
- **Deterministic output.** The same project gives byte-identical `proofs/` files:
  - types and defs in a stable order (dependencies first, then source order);
  - helpers numbered per declaration in source order;
  - imports sorted.
- **Every generated file starts with this header:**

  ```
  # Generated by efx <efx version> from <source path> (sha256:<first 16 hex of the source's hash>).
  # Do not edit: `efx verify` rewrites this file. bend <bendVersion>
  ```

  The prelude and errors files name `effectscript` and the package instead of a source path. The
  expected files in this plan write `# (header)` for these two lines.
- **The provable subset is spec §4's tables.** Anything else is opaque with a reason, never an
  error during build. Model diagnostics are EFX9421–EFX9425, and only `efx verify` and
  `efx print --to bend` show them.
- **Bend-reserved words** used as identifiers get a trailing `_`: `def`, `type`, `law`, `match`,
  `case`, `import`, `as`, `is`, `do`, `return`, `for`, `exs`, `where`, `with`. A `$` becomes `_d_`.
  Other non-ASCII identifier characters become `_u<hex>_`.
- **Diagnostics** (exact texts):
  - **EFX9411:** "proofs/ is stale: run `efx verify`"
  - **EFX9421:** "`<name>` has no written type here, so `<declaration>` stays out of the model"
  - **EFX9422:** "`===` compares references here: use `Equal.equals` to compare values"
  - **EFX9423:** "these modules import each other, so they stay out of the model: <list>"
  - **EFX9424:** "`<declaration>`'s recursion doesn't shrink an argument, so it stays out of the
    model"
  - **EFX9425:** "bend <found> isn't the pinned <bendVersion>: laws are only tested" (or "bend isn't
    installed: …")
- Nothing is published.

## Review Focus

1. **Copies.**
   - A variable used twice on one path and once on another needs `+`.
   - So does a pattern field used twice: `case Circle{+radius}`.
   - So does a scrutinee returned from its own arm: `+s`, which Bend accepts (checked on 2.0.35).
   - A parameter used only by a lifted helper does not.
   - Wrong `+` is a Bend "consumed more than once" error on valid code.
   - *(Task 5: golden `pure.efx`, `shapes.efx`)*
2. **Identifiers Bend can't take.**
   - A TypeScript variable named `type`, `case`, `match` or `law`.
   - Identifiers with `$` or non-ASCII letters.
   - Two helpers that would collide after escaping.
   - *(Task 3: printer tests)*
3. **String and number literals.**
   - Quotes, backslashes, newlines, accents and emoji round-trip into Bend strings (checked on 2.0.35).
   - Integers above 4294967295 print as `Nat.add(Nat.mul(hi, Nat.mul(65536n, 65536n)), lo)`.
   - Negative literals print as `Neg{|v| - 1}`.
   - Bend's checker computes `Nat` in unary, so a proof must keep big constants abstract; the skill
     says so (Task 14).
   - *(Task 3)*
4. **Opacity through several hops, and in any order.**
   - A law reaching an opaque function two calls away, defined below its caller, is reported with
     the first opaque thing it reaches and its location.
   - A cycle between functions is opaque, not a crash.
   - *(Task 8)*
5. **Bend failures `efx verify` must survive.**
   - `bend` is missing or the wrong version: laws are only tested, with EFX9425.
   - A proof makes the checker loop: a timeout (default 60 s per law, `--timeout`) makes that law
     *tested*, with "proof check timed out".
   - `bend` output the CLI doesn't recognize: *tested*, with the raw first line.
   - *(Task 12)*

**What `parseBendOutput` reads:**

- **Checked:** the first line is `ALL PROOFS CHECK` and the status is 0.
- **Open:** `SOME PROOFS FAIL` with `Error: <n> TODO(s) found.`
- **Failed:** `SOME PROOFS FAIL` with a `- expected`/`- observed` block or a `- message` line. Keep
  the first message, the `Location: <def>` line, and the whole output.
- **Unrecognized:** anything else.

`install-bend.ts [--to <dir>]` downloads
`https://github.com/bendlang/bend/releases/download/v<bendVersion>/bend-<bendVersion>-<os>-<arch>.tar.gz`.
It checks the archive's sha256 against `bendArchives`, then unpacks it to `<dir>`. The default
`<dir>` is `node_modules/.cache/bend/<bendVersion>`. It prints the path of `bin/bend`. It never
edits a shell file.

```python
# The EffectScript prelude for Bend models (ADR-0076): what Effect and TypeScript
# values become in a model, built on Base's native operations, with the lemmas
# proofs need. Generated models import it as `Efx`.
import Base

# Bool
# ----

def Bool.eq(a: Bool, b: Bool) -> Bool:
  match a b:
    case True{} True{}:
      True{}
    case True{} False{}:
      False{}
    case False{} True{}:
      False{}
    case False{} False{}:
      True{}

# a implies b; reads b first, so `implies(x, True{})` computes without x
def Bool.implies(a: Bool, b: Bool) -> Bool:
  match b:
    case True{}:
      True{}
    case False{}:
      Bool.not(a)

# the motive that tells True from False
def Bool.disc(b: Bool) -> Type:
  match b:
    case True{}:
      Unit
    case False{}:
      Empty

def Cmp.flip(c: Cmp) -> Cmp:
  match c:
    case LT{}:
      GT{}
    case EQ{}:
      EQ{}
    case GT{}:
      LT{}

# Exit
# ----

# The outcome of an effect, as Effect names it. Defects and interruption
# are not modeled.
type Exit<-E: Data, -A: Data> is Data:
  Failure{error: E}
  Success{value: A}

def Exit.is_failure(-E: Data, -A: Data, x: Exit<E, A>) -> Bool:
  match x:
    case Failure{e}:
      True{}
    case Success{v}:
      False{}

def Exit.is_success(-E: Data, -A: Data, x: Exit<E, A>) -> Bool:
  match x:
    case Failure{e}:
      False{}
    case Success{v}:
      True{}

# Int
# ---

# A whole number: Pos{n} is n and Neg{n} is -(n + 1), so each number has one
# form. Built on Base's Nat operations, which are native in compiled code.
type Int is Data:
  Pos{n: Nat}
  Neg{n: Nat}

def Int.of_nat(n: Nat) -> Int:
  Pos{n}

def Int.neg(x: Int) -> Int:
  match x:
    case Pos{0n}:
      Pos{0n}
    case Pos{1n+p}:
      Neg{p}
    case Neg{n}:
      Pos{1n+n}

def Int.sub_nat.fin(c: Cmp, +m: Nat, +n: Nat) -> Int:
  match c:
    case LT{}:
      Neg{Nat.sub(Nat.sub(n, m), 1n)}
    case EQ{}:
      Pos{0n}
    case GT{}:
      Pos{Nat.sub(m, n)}

# m - n, for naturals m and n
def Int.sub_nat(+m: Nat, +n: Nat) -> Int:
  Int.sub_nat.fin(Nat.cmp(m, n), m, n)

def Int.add(a: Int, b: Int) -> Int:
  match a b:
    case Pos{x} Pos{y}:
      Pos{Nat.add(x, y)}
    case Pos{x} Neg{y}:
      Int.sub_nat(x, 1n+y)
    case Neg{x} Pos{y}:
      Int.sub_nat(y, 1n+x)
    case Neg{x} Neg{y}:
      Neg{1n+Nat.add(x, y)}

def Int.sub(a: Int, b: Int) -> Int:
  match a b:
    case Pos{x} Pos{y}:
      Int.sub_nat(x, y)
    case Pos{x} Neg{y}:
      Pos{Nat.add(x, 1n+y)}
    case Neg{x} Pos{y}:
      Neg{Nat.add(x, y)}
    case Neg{x} Neg{y}:
      Int.sub_nat(y, x)

def Int.mul(a: Int, b: Int) -> Int:
  match a b:
    case Pos{x} Pos{y}:
      Pos{Nat.mul(x, y)}
    case Pos{x} Neg{y}:
      Int.neg(Pos{Nat.mul(x, 1n+y)})
    case Neg{x} Pos{y}:
      Int.neg(Pos{Nat.mul(1n+x, y)})
    case Neg{x} Neg{y}:
      Pos{Nat.mul(1n+x, 1n+y)}

# truncating division and its remainder, as JavaScript on safe integers;
# a division by zero answers 0 (JavaScript differs: avoid it in laws)
def Int.div(a: Int, b: Int) -> Int:
  match a b:
    case Pos{x} Pos{y}:
      Pos{Nat.div(x, y)}
    case Pos{x} Neg{y}:
      Int.neg(Pos{Nat.div(x, 1n+y)})
    case Neg{x} Pos{y}:
      Int.neg(Pos{Nat.div(1n+x, y)})
    case Neg{x} Neg{y}:
      Pos{Nat.div(1n+x, 1n+y)}

def Int.mod(a: Int, b: Int) -> Int:
  match a b:
    case Pos{x} Pos{y}:
      Pos{Nat.mod(x, y)}
    case Pos{x} Neg{y}:
      Pos{Nat.mod(x, 1n+y)}
    case Neg{x} Pos{y}:
      Int.neg(Pos{Nat.mod(1n+x, y)})
    case Neg{x} Neg{y}:
      Int.neg(Pos{Nat.mod(1n+x, 1n+y)})

def Int.cmp(a: Int, b: Int) -> Cmp:
  match a b:
    case Pos{x} Pos{y}:
      Nat.cmp(x, y)
    case Pos{x} Neg{y}:
      GT{}
    case Neg{x} Pos{y}:
      LT{}
    case Neg{x} Neg{y}:
      Nat.cmp(y, x)

def Int.is_lt(a: Int, b: Int) -> Bool:
  Cmp.is_lt(Int.cmp(a, b))

def Int.is_le(a: Int, b: Int) -> Bool:
  Cmp.is_le(Int.cmp(a, b))

def Int.is_gt(a: Int, b: Int) -> Bool:
  Cmp.is_gt(Int.cmp(a, b))

def Int.is_ge(a: Int, b: Int) -> Bool:
  Cmp.is_ge(Int.cmp(a, b))

def Int.is_eq(a: Int, b: Int) -> Bool:
  Cmp.is_eq(Int.cmp(a, b))

def Int.show(x: Int) -> String:
  match x:
    case Pos{n}:
      Nat.show(n)
    case Neg{n}:
      "-" ++ Nat.show(1n+n)

# List
# ----
# Templates that thread a reusable environment, for closures the emitter
# converts (ADR-0076): `xs.map((x) => x + k)` is `map_with(~lam, k, xs)`.

def List.map_with(~E: Data, ~A: Data, ~B: Data, ~f: @+e:E -> A -> B, +env: E, xs: List<&2, A>) -> List<&2, B>:
  match xs:
    case Nil{}:
      Nil{}
    case h <> t:
      f(env, h) <> List.map_with(~E, ~A, ~B, ~f, env, t)

def List.filter_with.pick(-A: Data, c: Bool, h: A, r: List<&2, A>) -> List<&2, A>:
  match c:
    case True{}:
      h <> r
    case False{}:
      r

def List.filter_with(~E: Data, ~A: Data, ~f: @+e:E -> @+x:A -> Bool, +env: E, xs: List<&2, A>) -> List<&2, A>:
  match xs:
    case Nil{}:
      Nil{}
    case +h <> t:
      List.filter_with.pick(A, f(env, h), h, List.filter_with(~E, ~A, ~f, env, t))

def List.foldl_with(~E: Data, ~A: Data, ~B: Data, ~f: @+e:E -> B -> A -> B, +env: E, xs: List<&2, A>, acc: B) -> B:
  match xs:
    case Nil{}:
      acc
    case h <> t:
      List.foldl_with(~E, ~A, ~B, ~f, env, t, f(env, acc, h))

def List.some_with(~E: Data, ~A: Data, ~f: @+e:E -> A -> Bool, +env: E, xs: List<&2, A>) -> Bool:
  match xs:
    case Nil{}:
      False{}
    case h <> t:
      Bool.or(f(env, h), List.some_with(~E, ~A, ~f, env, t))

def List.every_with(~E: Data, ~A: Data, ~f: @+e:E -> A -> Bool, +env: E, xs: List<&2, A>) -> Bool:
  match xs:
    case Nil{}:
      True{}
    case h <> t:
      Bool.and(f(env, h), List.every_with(~E, ~A, ~f, env, t))
```

- [ ] **Step 2: Add the lemmas as laws, then prove each.** The executing agent proves them with
  `bend bend/prelude.bend`. The statements are fixed and parse on 2.0.35:

```python
# Lemmas
# ------

law Bool.true_ne_false:
  for e: {True{} == False{} : Bool}
  Empty

law Nat.eq_refl:
  for +n: Nat
  {Nat.is_eq(n, n) == True{} : Bool}

law Nat.cmp_flip:
  for +a: Nat
  for +b: Nat
  {Nat.cmp(b, a) == Cmp.flip(Nat.cmp(a, b)) : Cmp}

law Int.eq_refl:
  for +x: Int
  {Int.is_eq(x, x) == True{} : Bool}

law Int.sub_self:
  for +x: Int
  {Int.sub(x, x) == Pos{0n} : Int}

law Int.not_gt_sub_ge_zero:
  for +a: Int
  for +b: Int
  for e: {Int.is_gt(a, b) == False{} : Bool}
  {Int.is_ge(Int.sub(b, a), Pos{0n}) == True{} : Bool}

law Int.add_sub_cancel:
  for +a: Int
  for +b: Int
  {Int.add(Int.sub(a, b), b) == a : Int}

law Int.add_comm:
  for +a: Int
  for +b: Int
  {Int.add(a, b) == Int.add(b, a) : Int}
```

```python
def Bool.true_ne_false(e):

    case 0n:
      {==}
    case 1n+p:
```

For the rest, follow these patterns:

- **`Int.eq_refl`:** `match x`, then `Nat.eq_refl(n)` in both arms.
- **`Int.not_gt_sub_ge_zero`:** the spike's `int_sub_ge` (private research note, spike `bank/`),

- **`Int.add_sub_cancel` and `Int.add_comm`:** these are the hardest. Case on both signs, then
  prove `Nat` lemmas about `Nat.sub`, `Nat.add` and `Nat.cmp`.

**Printer rules.**

- **Imports:**
  - `import Base` comes first.
  - Then `import <relative path> as <alias>` for every file referenced, sorted by path.
  - Aliases: `Efx` (prelude), `Err` (errors), `T` (the module's own `types.bend`); other modules use
    PascalCase of the last path segment (`Bank`), plus a `T` suffix for their types (`BankT`).
- **Order:**
  - Types come in declaration order.
  - Defs are topologically sorted by calls: a callee before its caller, self-recursion ignored,
    ties in `origin` order.
- **Literals:**
  - An `IntLit` prints `Efx.Pos{<n>n}` or `Efx.Neg{<|n|-1>n}`.
  - A `NatLit` above 4294967295 prints `Nat.add(Nat.mul(<hi>, Nat.mul(65536n, 65536n)), <lo>)`,
    recursively.
  - A `StringLit` escapes `\` `"` and newline; other characters go as they are.
- **Layout:** two-space indentation, one `case` per line, one blank line between definitions, and the
  `comment` as a `# …` line above its def.
- **Copies:** `+` before every parameter and pattern binder in `copies(def)`.
- **Lets:** a `Let` whose value is a constructor, a literal or a pair prints as
  `name = {value : T}`. Bend can't infer those ("an annotated term (cannot infer)", seen on
  2.0.35); calls and variables print bare.

**Interfaces:**
- `lowerFunction(decl: Node, module: ModuleEnv, env: Env): { readonly defs: ReadonlyArray<Def> } | { readonly opaque: Reason }`
  where `Reason = { readonly message: string; readonly file: string; readonly line: number }`.
- `copies(def: Def): ReadonlySet<string>` returns every parameter or pattern binder used more than
  once on some path. A `match` on a variable counts as one use of it. Arms are alternatives, so
  their counts don't add up.
- `infer(expression, scope): BType | undefined`. It synthesizes types for:
  - literals (an integer literal takes the type of the other operand, or `Int`);
  - variables;
  - calls (declared results);
  - field reads;
  - operators;
  - conditionals (both branches must agree).

  When it returns `undefined` for a binding the model needs, the declaration is opaque with EFX9421.
- **Lifting a computed condition** (`if`, `? :`, `&&`/`||` with effects aside):
  - The condition becomes `<decl>.if<n>(cond, <free variables of both branches, in order of first
    use>)`, whose body is `match c`.
  - A branch that calls the declaration itself gets that call computed in the caller and passed in,
    because a helper may not call below it.
- **Recursion:** only over a pattern piece of a parameter. That parameter moves first in the def.
  Anything else is EFX9424.
- **`let`:** a local that is reassigned outside a loop gets a new name per assignment (`total`,
  `total1`, …), so the model has only lets. Inside a `for … of`, Task 7's loop helper carries it.
- **Template literals:** `` `a${n}b` `` lowers to `"a" ++ Efx.Int.show(n) ++ "b"` for an `Int`. A
  `string` goes in as it is. A `boolean` becomes `Bool.show`, which is written into the prelude if
  Base lacks it. Any other interpolated type is opaque.
- **Several scrutinees** are ordered the way Bend requires: a pattern variable takes its
  scrutinee's place, so after `case e <> rest` on `evs`, `e` is matched before parameters that come
  after `evs`.

- **`console.*` and `Effect.log*`:** dropped.
- **`await [a, b]` / `await { a, b }`:** lowered left to right when no element touches modeled
  state (none can, until Plan 27). Otherwise opaque.
- **`defer`, `using … await`, `finally`:** dropped when their bodies only log. Otherwise opaque.

- **Exits.** An exit's `.value` is modeled only where a guard has narrowed it:

  without checking it".

**Steps of `verifyProject`, as spec §6.1 1–5 and 8:**

1. **Property tests.** For each module with laws:
   - import `<module>?laws` through the register hooks (Plan 24 Task 4);
   - call its `$efxRunLaws` with a collecting shim `{ effect: (name, f) => … }`;
   - run each `check(law, { runs, seed })` from `effectscript/laws`.

   A `Falsified` or `Exhausted` result makes the law *fails*, with the formatted failure (its shrunk
   input) as the note. A law with `requires` notes "requires discarded <n> inputs", from the check
   result's `discards`.
2. **Model.** `toBend` the project. Write it with `writeProofs`, or with `--check` compare with
   `staleProofs` and fail with EFX9411.
3. **Bend.** `findBend()`:
   - **missing or another version:** EFX9425, and every passing law stays *tested*, with "bend
     missing" or "bend <v> isn't the pinned <bendVersion>";
   - **otherwise,** for every passing, provable law that has `<law>.proof.bend`, run
     `runBend(bend, "<law>.proof.bend", { cwd: <module dir>, timeoutMs })`. Run at most
     `os.availableParallelism()` at a time.
4. **Outcomes:**

   | Bend's answer | Rung | Note |
   | ------------- | ---- | ---- |
   | Checked | *proved* | |
   | Failed | *tested* | "proof needs repair: <message> at <location>" |
   | Open | *tested* | "proof has <n> TODO(s)" |
   | TimedOut | *tested* | "proof check timed out" |
   | Unrecognized | *tested* | "bend said: <first line>" |
   | No proof file | *tested* | "no proof yet: efx verify --explain <law>" (`--explain` lands in Plan 26) |
   | Not provable | *tested* | "not provable: <reason>" |

5. **Output.** Print spec §6.3's layout, grouped by file, with a closing line counting the laws per
   rung.
6. **Exit code.** 1 when any law *fails*, the lock or `--check` fails, or (with `--strict`) a law
   has a proof file that doesn't check. Otherwise 0.

The `verify` command in `main.efx`:

```efx
/** Test every law, model the project in Bend, and check the proofs (spec: proofs design §6) */
export const verify = Command.make("verify", {
  paths: Argument.String("paths").pipe(Argument.variadic(), Argument.withDescription("Files or directories (default: the project)")),
  law: Flag.String("law").pipe(Flag.optional, Flag.withDescription("Only this law")),
  runs: Flag.Int("runs").pipe(Flag.withDefault(100), Flag.withDescription("Inputs per law")),
  seed: Flag.Int("seed").pipe(Flag.optional, Flag.withDescription("The property tests' seed, to repeat a run")),
  check: Flag.Boolean("check").pipe(Flag.withDefault(false), Flag.withDescription("CI: fail if proofs/ is stale; write nothing")),
  strict: Flag.Boolean("strict").pipe(Flag.withDefault(false), Flag.withDescription("A proof that doesn't check is an error")),
  timeout: Flag.Int("timeout").pipe(Flag.withDefault(60), Flag.withDescription("Seconds Bend gets per law"))
}, effect ({ paths, law, runs, seed, check, strict, timeout }) => {
  const result = await promise(() => verifyProject(process.cwd(), {
    paths,
    law: law._tag === "Some" ? law.value : undefined,
    runs,
    seed: seed._tag === "Some" ? seed.value : undefined,
    check,
    strict,
    timeoutMs: timeout * 1000
  }, { out: (line) => process.stdout.write(`${line}\n`), err: (line) => process.stderr.write(`${line}\n`) }))
  await exitWith(result.code)
}) |> Command.withDescription("Test every law, model the project in Bend, and check the proofs")
```

```efx
// packages/effectscript/examples/src/order.efx
/** Where an order stands. */
export schema OrderState =
  | Pending {}
  | Paid {}
  | Shipped {}
  | Cancelled {}

/** What can happen to an order. */
export schema OrderEvent =
  | Pay {}
  | Ship {}
  | Cancel {}

/** What one event does to an order. */
export const step = (state: OrderState, event: OrderEvent): OrderState =>
  match (state) {
    when Pending: match (event) { when Pay: new Paid(); when Ship: state; when Cancel: new Cancelled() }
    when Paid: match (event) { when Pay: state; when Ship: new Shipped(); when Cancel: new Cancelled() }
    when Shipped: state
    when Cancelled: state
  }

/** Every event, in order, from a starting state. */
export const replay = (events: ReadonlyArray<OrderEvent>, from: OrderState): OrderState => events.reduce(step, from)
```

```efx
/** An order is never shipped unless it was paid. */
```
